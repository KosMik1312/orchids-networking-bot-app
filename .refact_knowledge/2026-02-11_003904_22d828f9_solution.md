# Solution
Ниже — **план решения по шагам** (без реализации кода). Он опирается на текущую структуру проекта из контекста: `ADMIN_IDS` уже читается из окружения в `bot/config.py`, проверка админов уже есть в `bot/middleware/admin_middleware.py`, FastAPI уже умеет JWT (`bot/auth_token.py`, `bot/api_server.py`), а MiniApp — это SPA со “скринами” в `src/app/page.tsx`.

---

## 1) Что именно “ломается” сейчас / почему нужно менять

1) **Админка сейчас живёт в Telegram-команде `/admin`** (aiogram), а вы хотите **админку внутри MiniApp** (Next.js UI).
2) **Нужна надёжная проверка админа по Telegram ID**:
   - в боте это уже делается через `AdminMiddleware` + `ADMIN_IDS`;
   - но в MiniApp/через API **такой проверки пока нет**.
3) **В MiniApp нет экранов/логики для администрирования**, и нет API-эндпоинтов для:
   - списка пользователей,
   - списка мероприятий (у вас это по факту похоже на `DinnerSlot`),
   - просмотра участников мероприятия,
   - групп пользователей и таргет-рассылки по группам.

---

## 2) Целевая архитектура (как будет работать)

### 2.1. Источник прав администратора
**Единый источник**: переменная окружения `ADMIN_IDS` (как у вас уже заведено в `bot/config.py`).

- **Бот**: проверяет `/admin` через `AdminMiddleware`.
- **FastAPI**: будет проверять доступ к `/api/admin/*` через dependency “require_admin”, которая:
  1) достаёт `user_id` из JWT (`Authorization: Bearer ...`) через `validate_user_token()`,
  2) проверяет `user_id in ADMIN_IDS`,
  3) иначе отдаёт `403`.

Так админку нельзя будет “подделать” простым открытием URL MiniApp.

---

## 3) Шаги реализации (MVP → расширение)

### Шаг 1. Сделать вход в админку через `/admin` в боте (но UI уже в MiniApp)
**Что меняем в боте:**
- Команда `/admin` остаётся.
- Если `is_admin = True`, бот **не показывает старую inline-панель**, а отправляет кнопку:
  - “Открыть админку” (WebApp-кнопка или ссылка),
  - URL = `MINIAPP_URL + "?screen=admin&token=<jwt>"`.
- JWT генерируем уже готовой функцией `generate_user_token(user_id)` (у вас есть `bot/auth_token.py`).

**Corner cases:**
- `MINIAPP_URL` не задан → бот отвечает понятной ошибкой.
- `SECRET_KEY` не задан → токен не сгенерируется → тоже явная ошибка администратору.
- Пользователь не админ → как сейчас: “нет прав”.

---

### Шаг 2. Добавить в FastAPI “админские” эндпоинты (строго защищённые)
Добавляем новый набор роутов, например:

- `GET /api/admin/me` → вернуть `{ user_id, is_admin: true }` (для фронта, чтобы понять что показывать).
- `GET /api/admin/users?limit=&offset=&q=` → список пользователей (пагинация обязательно).
- `GET /api/admin/slots` → список всех “мероприятий” (у вас это `DinnerSlot`).
- `GET /api/admin/slots/{slot_id}` → детали слота.
- `GET /api/admin/slots/{slot_id}/participants` → список пользователей, кто купил/забронировал (по `Booking` + статус).
- `POST /api/admin/slots` → создание мероприятия (аналог текущего FSM создания слота).
- `PATCH /api/admin/slots/{slot_id}` → активация/деактивация, изменение лимита мест и т.д.

**Важно про “купивших”**  
Сейчас покупка/оплата у вас в `Payment`, а бронирования в `Booking`. Нужно заранее решить правило:
- участник считается “купившим”, если:
  - `Booking.status in ('confirmed')` **или**
  - есть `Payment.status == 'succeeded'` связанный с booking_id.
  
Я предложу сделать единое правило и отдать фронту два списка: `booked` и `paid/confirmed`, чтобы избежать путаницы.

**Corner cases:**
- `AUTH_DISABLED=true` (режим разработки):  
  для админских эндпоинтов лучше **НЕ разрешать** работу без токена вообще, иначе любой сможет подставить `userId`. То есть: `AUTH_DISABLED` может оставаться для user-endpoints, но admin-endpoints всё равно требуют токен.
- Пагинация: тысячи пользователей → нельзя отдавать “копи паст из БД” одним махом.
- Изменение `max_people` меньше `current_bookings` → запрещаем или требуем явное подтверждение/авто-ограничение.
- Slot не найден → 404.
- Возврат согласованного формата данных (boolean vs number).

---

### Шаг 3. Группы пользователей (для таргет-рассылки и фильтрации)
Сейчас в БД **нет сущности “группа”**. Нужно добавить.

**Надёжный вариант (рекомендуемый):**
- Таблица `groups`: `id`, `name`, `created_at`
- Таблица связей many-to-many `user_groups`: `user_id`, `group_id`, unique(user_id, group_id)

Эндпоинты:
- `GET /api/admin/groups`
- `POST /api/admin/groups`
- `DELETE /api/admin/groups/{id}`
- `POST /api/admin/groups/{id}/members` (добавить пользователей пачкой)
- `DELETE /api/admin/groups/{id}/members/{user_id}`

**Corner cases:**
- Дубликаты (уникальный индекс)
- Удаление группы с участниками (CASCADE или ручное удаление)
- Добавление несуществующего user_id → 404/частичный успех (лучше “частичный” с отчётом)

---

### Шаг 4. Рассылка по группам (и/или по участникам мероприятия)
Тут два пути:

**Вариант A (проще в вашей архитектуре):** рассылку делает FastAPI, используя `BOT_TOKEN` и Telegram Bot API.
- `POST /api/admin/broadcast` с параметрами:
  - `group_ids[]` или `slot_id` (по кому),
  - `text`,
  - опционально кнопка/ссылка.
- FastAPI отправляет сообщения через Telegram API.

**Corner cases (Telegram-рассылка):**
- лимиты Telegram (нужна задержка между отправками, батчинг)
- пользователь заблокировал бота → ловим ошибку, продолжаем
- часть отправок упала → возвращаем отчёт: `sent/failed + список причин`

**Вариант B (более “чистый”):** рассылку делает сам бот как отдельная задача/воркер, а FastAPI только создаёт “broadcast job” в БД.  
Это сложнее, но надёжнее для больших рассылок.

---

### Шаг 5. MiniApp: экран(ы) админки в существующей стилистике
У вас сейчас навигация — это `useState(currentScreen)` в `src/app/page.tsx`. Значит:

1) Добавляем новые `Screen`: например `"admin" | "admin_users" | "admin_slot" | "admin_groups"`.
2) Добавляем компоненты, стилизуем как остальные (белые карточки, скругления, `COLORS.primary`, bottom-nav можно скрывать в админке или оставить).
3) При заходе на `screen=admin`:
   - читаем `token` из query,
   - зовём `GET /api/admin/me`:
     - если 200 → показываем админ-дашборд,
     - если 401/403 → экран “Нет доступа”.

**Corner cases:**
- Открыли без token → показываем “Откройте админку через бота”.
- Token истёк (24ч) → просим заново открыть `/admin`.
- CORS: домен MiniApp должен быть в `allow_origins` FastAPI (`bot/api_server.py`).

## 4) Назначение администраторов в `start_services.sh` (как вы просили)
Сейчас `start_services.sh` умеет старт/стоп/логи/очистка БД. Добавляем пункт меню, например:

**“9) Настроить ADMIN_IDS”**
- Скрипт:
  1) просит ввести Telegram ID через запятую,
  2) валидирует: только числа, убирает пробелы, удаляет дубликаты,
  3) записывает/заменяет строку `ADMIN_IDS=...` в `bot/.env` (создаёт файл если нет),
  4) предлагает перезапустить сервисы.

**Corner cases:**
- нет прав на запись `.env` → понятная ошибка
- `.env` отсутствует → создаём
- строка `ADMIN_IDS` уже есть → корректно заменяем (sed/awk)
- ввод пустой → делаем список пустым (или запрещаем, на ваше решение)

## 5) Важное замечание про “правильное чтение/запись профиля” (нашёл потенциальный баг)
В `bot/api_server.py` Pydantic-модель `UserProfile` **не содержит `meeting_metro`, `meeting_days`, `meeting_time_from`, `meeting_time_to`, а также `format`**, хотя фронт их отправляет (`src/app/page.tsx` → `updateProfile({ meeting_metro: ..., ... format, goal ... })`).

Даже если pydantic сейчас “молча игнорирует лишние поля”, у вас получится ситуация: **фронт думает что сохранил, а бэк их выкинул**. Для админки это не критично, но для “данные должны корректно сохраняться” — важно.

Я предлагаю включить это в план работ как отдельный мини-шаг: **синхронизировать DTO FastAPI с тем, что реально отправляет MiniApp**.

## 6) Альтернативные способы (если основной подход не подойдёт)

### Альтернатива 1: Админов хранить в БД, а `start_services.sh` только добавляет первого “root admin”
- Таблица `admins` или флаг `users.is_admin`.
- Плюс: можно назначать админов из самой админки.
- Минус: нужна миграция и безопасный “bootstrap”.

### Альтернатива 2: Авторизация MiniApp через Telegram `initData` (без JWT от бота)
- MiniApp передаёт `initData` на бэк,
- бэк валидирует подпись Telegram (по bot token),
- достаёт user_id и проверяет `ADMIN_IDS`.
- Плюс: админку можно открывать без команды `/admin`.
- Минус: реализация чуть сложнее, и всё равно нужно аккуратно сделать проверку подписи.

### Альтернатива 3: Оставить “опасные” операции (рассылки) в боте, а MiniApp только как UI
- MiniApp создаёт “задания” (broadcast job),
- бот читает их из БД и выполняет.
- Плюс: меньше рисков с Telegram API и лимитами внутри FastAPI.
- Минус: сложнее связка двух сервисов.
